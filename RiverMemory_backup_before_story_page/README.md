# RiverMemory

Historical river water quality and environmental intelligence for the Triveni Sangam, Prayagraj (Ganga and Yamuna).

FastAPI + SQLAlchemy backend, React + Vite frontend. A fresh database contains no observations. Load the supplied
Phase 3 workbook with the idempotent importer below, or import other datasets through the Admin page.

The public opening page is an illustrated, source-cited introduction to the Triveni Sangam at `/`. The earlier
RiverMemory overview remains available at `/about`; environmental data pages remain accessible from the site
navigation and the story's final transition.

## Run (two terminals)

**Backend** (PowerShell, from the project root)
```powershell
cd .\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts\init_env.py
python -m scripts.create_admin admin
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
API docs: http://127.0.0.1:8000/docs · Health: http://127.0.0.1:8000/api/health

**Frontend** (in a second PowerShell terminal)
```powershell
cd .\frontend
npm install
npm run dev
```

## Fixing the errors you reported
- **`WinError 10013` / port 8000 in use**: check the listener with
  `Get-NetTCPConnection -LocalPort 8000 -State Listen`. Verify its PID and command line before taking action. If it is
  already this project's Uvicorn server, reuse it; do not start a second server or stop an unrelated process.
- **`JWT_SECRET must be configured with at least 32 bytes`**: configuration loads `backend/.env` independently of
  the launch directory. Keep a secret of at least 32 bytes in that file; do not commit or share it. A missing/short
  secret disables admin login and writes, not public reads. `/api/health` reports whether auth is configured.
- **"Could not reach the API"**: the frontend calls `/api/...` through Vite's proxy to `127.0.0.1:8000`, and
  `/api/health` is public. Reuse an existing backend if the port is occupied. `CORS_ORIGINS` includes
  `http://localhost:5173` and `http://127.0.0.1:5173` for direct API deployments.

## Importing data (Admin → Import)
CSV only, max 10 MB, UTF-8. Preview first, then commit. Download header templates from the import page.
- **water_quality**: `date, station, river, latitude, longitude` + any of `ph, do, bod, cod, temperature, conductivity, nitrate, total_coliform, fecal_coliform`
- **rainfall**: `date, rainfall_mm, location, kind (gridded|gauge), resolution` (location/kind may be given on the form)
- **stations**: `station, river, latitude, longitude`

Rules: only Ganga and Yamuna; dates `YYYY-MM-DD`, `DD-MM-YYYY` or `DD/MM/YYYY`; blank/NA/BDL cells are stored as missing;
non-numeric or implausible values reject the row (reported, never silently fixed); duplicates are skipped and counted;
coordinates must lie within India. Register a data source first so records keep their provenance.

## Prayagraj 2022 datasets (Phase 3)
The cleaned workbook and CSV extracts live in `data/`. The workbook importer reads the named sheets and can be safely
rerun; it does not drop tables or duplicate records:
- `RiverMemory_Phase3_Cleaned_Dataset.xlsx`: source workbook (`Water_Quality_Clean`, `Rainfall_Clean`,
  `Station_Coordinates`).
- `rainfall_prayagraj_2022.csv`: 365 daily IMD 0.25° grid-cell values, already in the rainfall import format
  (`kind=gridded`).
- `water_quality_ranges_2022.csv`: 24 annual **min–max ranges** (stations 1046, 1049, 1069). These are not dated
  readings, so they are stored in their own table (`water_quality_ranges`) and never enter trends, correlations or
  rainfall comparisons. Shown in the "Annual min–max ranges" card on the Water quality page; API: `GET /api/water-quality/ranges`.

```powershell
cd .\backend
python -m scripts.load_phase3_data
```
The loader registers unverified sources, adds the 365 rainfall values and 24 ranges, and stores the
`RF-TARGET`/`RF-GRID` rainfall reference points separately from water-quality stations. It never estimates station
coordinates. Expected checks: annual rainfall 560.77 mm, 47 days ≥2.5 mm, 66 days >0 mm, and wettest day
2022-07-25 at 51.34 mm. `/insights` shows the 2022 Year in Review; API: `GET /api/insights/year/2022`.

The CPCB report/page/period behind the ranges remains unverified. Nitrate basis (NO3 vs N) is not stated.
Conductivity is displayed as µS/cm; the supplied source unit is µmhos/cm.

## River Explorer
`/river-explorer` is a separate Leaflet experience; the original monitoring map remains at `/map`. Its compact
local GeoJSON is generated by `frontend/scripts/build-river-explorer-data.mjs` from Natural Earth 1:10m river
centerlines and populated places at pinned revision
[`ca96624a56bd078437bca8184e78163e5039ad19`](https://github.com/nvkelso/natural-earth-vector/tree/ca96624a56bd078437bca8184e78163e5039ad19).
Natural Earth data is public domain. To refresh the local file, run `npm run river-data` from `frontend` (requires
network access); the app itself serves the checked-in subset and does not download global geometry in the browser.
The map uses OpenStreetMap tiles and attribution; Ganga/Yamuna source-region and Sangam locality markers link to
their OpenStreetMap place records.

The subset contains selected named line features and nearby populated places, not a complete river network.
Natural Earth cartographic lines are generalized and do not verify exact headwaters, lengths, endpoints, or
tributary relationships. City points are selected within 25 km of a mapped line and are not confirmed riverbank
locations. The source-region markers indicate Gangotri/Yamunotri localities, not glacier headwaters. Godavari is
listed but has no matching line in this release; the explorer intentionally does not invent a route. Saraswati is
explained as religious and historical context without a mapped modern or underground course.

RiverMemory monitoring stations appear only when database coordinates and source provenance are verified.
Currently supplied station coordinates/provenance do not meet that requirement, so none are plotted; rainfall
reference points and annual water-quality ranges are never shown as river stations or dated observations.

## Notes and limits
- Tables are created additively with `create_all`; existing tables are never dropped. For schema changes on a
  populated database, add Alembic migrations before altering columns.
- Screening uses CPCB Class B (outdoor bathing) limits: pH 6.5-8.5, DO ≥ 5, BOD ≤ 3, total coliform ≤ 500 MPN/100 mL.
  Indicative only; not a drinking-water assessment. Verify against the current CPCB notification.
- River centre-lines and study-area boundaries are not included (no verified geometry); the map shows only imported coordinates.
- Correlation needs ≥ 10 paired complete months; otherwise "insufficient data" is shown.
